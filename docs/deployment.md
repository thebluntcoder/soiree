# Deployment

## Backend — Railway

Build: `backend/Dockerfile`. Start (from `railway.toml`):

```
alembic upgrade head && uvicorn app.main:app --host 0.0.0.0 --port $PORT
```

`alembic upgrade head` runs on every deploy. The initial migration is
**idempotent** (it inspects the DB and only creates missing tables), so it
is safe against a database that predates Alembic adoption — such a database
just records the version and moves on.

### Required env vars

| Var | Example |
|---|---|
| `ANTHROPIC_API_KEY` | `sk-ant-...` |
| `APP_ENV` | `production` |
| `SECRET_KEY` | any long random string |
| `ALLOWED_ORIGINS` | `["https://soiree-blue.vercel.app"]` |
| `REDIRECT_URI` | `https://soiree-blue.vercel.app/auth/callback` |
| `DATABASE_URL` | injected by Railway Postgres (`postgresql://…` is auto-rewritten to `+asyncpg`) |
| `REDIS_URL` | injected by Railway Redis (`rediss://` → SSL is auto-detected) |

> If `ALLOWED_ORIGINS` is set as a Railway variable it overrides the default
> in `config.py`. It accepts a JSON array or a comma-separated string.

The plan-generation endpoint no longer hard-codes any CORS header —
`CORSMiddleware` echoes the request Origin when it is in `ALLOWED_ORIGINS`.
The Vercel origin must be listed there for `demo.html` to reach the API.

## Frontend — Vercel

Primary UI is the static `frontend/public/demo.html`
(`https://soiree-blue.vercel.app/demo.html`). It calls the Railway API
directly and picks the base URL by hostname:

```js
const API_BASE = location.hostname === 'localhost'
  ? 'http://localhost:8000'
  : 'https://soiree-production.up.railway.app';
```

The Next.js app under `frontend/src/` needs `NEXT_PUBLIC_API_URL` and proxies
`/api/*` to it via `next.config.js` rewrites.

## Swiggy OAuth redirect URIs

Whitelisted with Swiggy:

```
https://soiree-blue.vercel.app/auth/callback
http://localhost/callback
http://localhost
http://127.0.0.1  (+ /callback)
```

Local OAuth needs the frontend on port 80 (`sudo npm run dev -- -p 80`) and
`REDIRECT_URI=http://localhost/auth/callback` in `backend/.env`.

## Database migrations

```
cd backend
alembic upgrade head          # apply
alembic downgrade -1          # roll back one
alembic revision --autogenerate -m "what changed"   # after a model change
```

Models are never created by `create_all` — Alembic is the only path.
`script.py.mako` imports `sqlmodel` so autogenerated files referencing
`sqlmodel.sql.sqltypes.*` run without edits.
